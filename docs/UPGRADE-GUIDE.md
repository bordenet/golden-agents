# Upgrade guide

Audience: an AI agent working in a consumer repo that was generated by
golden-agents 1.4.x before this fix stack. Example consumer:
https://github.com/bordenet/superpowers-plus/

This guide matches the generator on `main` after items 1-21 and design v2
sections A-H. Section I is the eval fixture. Claude Code and Codex have no
score. The Cursor column has one run, and the two columns of that run match.
The commit `26d0b82` does not have the safe-write, backup, or stamp
behavior described here.

Do not assume templates or the script live at `$HOME/.golden-agents`. Run
`generate-agents.sh` from the golden-agents checkout that contains these
fixes. Pass the consumer repo with `--path`.

Do not edit `generate-agents.ps1`. It only runs the shell script.

## 0. Self-test the generator checkout

Before upgrading consumers, confirm the golden-agents checkout is complete and
executable:

```bash
/path/to/golden-agents/generate-agents.sh --self-test
```

This checks that each `lib/golden-agents/part*.sh` is at least 1000 bytes, that
the head is not a truncated path stub, that `bash -n` passes, and that
`--version` runs. A bad checkout fails here instead of mid-`--upgrade --apply`
or with exit 127 from a missing `+x` bit.

`--upgrade` runs the same checks automatically. Use `--self-test` alone when
you only want the health check.

When section 2 timestamped backups already exist and you are applying many
upgrades, pass `--no-backup` with `--apply`, `--migrate`, or `--adopt` so the
script skips `AGENTS.md.backup` and other script-written `.bak` copies:

```bash
/path/to/golden-agents/generate-agents.sh --upgrade --apply --no-backup --path=/path/to/consumer
```

## 1. Detect the generator version

Read `AGENTS.md`. If that name is absent and `Agents.md` is a different file,
read `Agents.md` too.

1. If a line matches
   `<!-- golden-agents:stamp version=VERSION updated=YYYY-MM-DD -->`,
   the generator version is `VERSION`.
2. Otherwise, if the header contains `> **Generated by**:` with `v1.4.` and
   the file contains both `<!-- GOLDEN:framework:start -->` and
   `<!-- GOLDEN:framework:end -->`, treat it as 1.4.x from before the stamp.
   Upgrade inserts a stamp when the file has none. An existing stamp keeps its
   date and version when the framework block is unchanged.
3. If there is no stamp and no framework marker pair, stop. Ask a human.
   Do not write.

## 2. Back up every guidance file before any write

Copy each file that exists. Use a timestamp the shell can format without
GNU `date -d`:

```bash
ts=$(date +%Y%m%d-%H%M%S)
bak() {
    src=$1
    dest="${src}.${ts}.bak"
    n=1
    while [ -e "$dest" ]; do
        dest="${src}.${ts}.bak-${n}"
        n=$((n + 1))
    done
    cp "$src" "$dest"
    echo "$dest"
}
```

Back up, when present:

- `AGENTS.md`
- `Agents.md` only when it is a different file from `AGENTS.md`
  (`[ ! AGENTS.md -ef Agents.md ]`)
- `CLAUDE.md`
- `GEMINI.md`
- `CODEX.md`
- `AGENT.md`
- `COPILOT.md`
- `.github/copilot-instructions.md`
- `.ai-guidance/invariants.md`

Do not add `*.bak` to `.gitignore`.

`--upgrade --apply` also writes `AGENTS.md.backup`. That copy is in addition
to the timestamped `.bak`, not a substitute. `--adopt` and `--migrate` write
their own timestamped `.bak` files and, for adopt, `AGENTS.md.original`.

## 3. Upgrade without losing project text

Preview first. The preview must not change the file.

```bash
/path/to/golden-agents/generate-agents.sh --upgrade --path=/path/to/consumer
```

Read the diff before applying.

- Text after `<!-- GOLDEN:framework:end -->` must be unchanged, except when
  content moves out of the markers: a bootstrap that was inside the
  framework is moved to immediately after the end marker; a numbered
  quality-gate block whose labels are not Lint, Build, Test, or Coverage
  moves the same way; any other non-empty interior line that does not
  appear anywhere in the upgraded file is appended once after the end
  marker. None of these are deleted. Preview prints
  `preserving N hand-written line(s) from inside managed block → after end
  marker:` and lists each line. A bootstrap the project already had below
  the marker must still be there, once, and must not be duplicated.
  `--superpowers` adds the template block only when the file does not
  already contain the bootstrap.
- If a command the project actually runs becomes `UNVERIFIED: confirm`, stop.
  Do not apply. A matching tail does not make that replacement safe. Show
  the diff to a human.
- A `<!-- golden-agents:modules ... -->` comment next to the stamp, or
  immediately before the framework start when the file has no stamp, is
  expected. Do not delete it.

Then apply:

```bash
/path/to/golden-agents/generate-agents.sh --upgrade --apply --path=/path/to/consumer
```

Rules:

- A plain run (no `--upgrade`, `--adopt`, or `--migrate`) that finds a
  non-generated redirect or any existing `AGENTS.md` must exit 1 and write
  nothing. Do not delete those files to make a plain run succeed.
- Use `--upgrade` only when both framework markers are present.
- Use `--migrate` or `--adopt` only when the script tells you to, and only
  after the backups in section 2.
- Do not overwrite an existing `.ai-guidance/invariants.md`. The script keeps
  it. If the file is absent, the script creates it from the template.

## 3b. Expect large diffs and redirect noise

`--upgrade --apply` rewrites the framework block. The diff is often large even
when project text after the end marker is unchanged. That is normal.

Timestamped `.bak` files and `AGENTS.md.backup` are local safety copies. Delete
them after you verify the upgrade, or pass `--no-backup` when section 2 backups
already exist and you do not want more script-written copies.

Redirect preview lines distinguish kept vs retired files:

- Kept (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`): a missing
  file is `would write … (@AGENTS.md import)`. An existing generated stub is
  `would rewrite … to @AGENTS.md import (kept redirect; replaces old stub)`.
- Retired (`AGENT.md`, `CODEX.md`, `COPILOT.md`): a generated stub is
  `would remove … (matches old generated stub; … are retired)`. A hand-written
  copy is left alone.

When a consumer repo gates commits on LOC or conventional-commit prefixes,
commit the upgrade as `chore(agents):` (or the repo's equivalent chore prefix)
so the guidance refresh is not blocked as a feature change.

## 4. Verify with runnable checks

In the consumer repo, after `--upgrade --apply`:

```bash
# Both markers still exist.
grep -n 'GOLDEN:framework:start' AGENTS.md
grep -n 'GOLDEN:framework:end' AGENTS.md

# Project text after the end marker.
awk 'f { print } index($0, "<!-- GOLDEN:framework:end -->") { f = 1 }' AGENTS.md > /tmp/after-project.txt
awk 'f { print } index($0, "<!-- GOLDEN:framework:end -->") { f = 1 }' AGENTS.md.*.bak > /tmp/before-project.txt
```

If the only new tail text is content that moved out of the framework
(bootstrap, custom quality gates, or hand-written interior lines listed
under `preserving N hand-written line(s)…`), or a template block added
because this run passed `--superpowers`, delete that added block from
`/tmp/after-project.txt`. The moved bootstrap is the lines the old file
had inside the framework markers, starting at
`### Optional: Superpowers integration` or at the
`superpowers-augment.js bootstrap` line. Hand-written lines are the exact
strings the preview listed. Then run:

```bash
cmp /tmp/before-project.txt /tmp/after-project.txt
```

`cmp` must exit 0. If it does not, restore `AGENTS.md` from the `.bak` and
stop. Do not leave the applied file in place. Any other tail difference is
a failed upgrade.

In the golden-agents checkout:

```bash
shellcheck generate-agents.sh
bats test/safe-write.bats test/data-loss.bats test/upgrade.bats test/stamp.bats
```

## 5. Recover a redirect that was replaced by a stub

Look for a modification that turned real content into a short generated file:

```bash
git log --oneline --diff-filter=M -- CLAUDE.md GEMINI.md CODEX.md .github/copilot-instructions.md AGENTS.md
```

Show the earlier blob. Do not restore it yourself.

```bash
git show COMMIT:CLAUDE.md
```

If that blob is real project text and the worktree file is a stub, print both
and stop. A human decides whether to put the old content back.

## 6. What the upgrade already does

Sections A-H of `docs/DESIGN-v2.md` are in this generator. `--upgrade --apply`
writes the redirect imports, the module copies, the scoped rules, the
`<!-- golden-agents:modules ... -->` comment, the current template wording,
the token estimate on stdout, the human-merge self-manage block, and the
detected quality gates. Do not copy those in by hand.

Pass `--superpowers` only when the consumer asked for a bootstrap the file
does not already have. The block is written after
`<!-- GOLDEN:framework:end -->`. A bootstrap already in the file is kept
there. One that sits inside the framework is moved below the end marker
on the first upgrade and left there after that. Upgrade does not invent
the block when the file never had it.

Gate detection matches only the exact names `lint`, `test`, `build`, and
`coverage`. A step named `Run BATS tests` or `Run ShellCheck` does not match.
On a new file, an unmatched gate keeps the template command and is prefixed
with `UNVERIFIED: confirm`. If `package.json`, a Makefile, a justfile,
`pyproject.toml`, or a workflow file is present and does not define that
gate name, the gate is omitted instead of invented, including a coverage
percentage the manifest does not define. On upgrade, a command
already in the quality-gate block is kept when it is that language's
template command, or when it matches no selected language's template. A
coverage line with no backtick command is kept whole, including any project
sentence after the percentage. A numbered gate whose label is not Lint,
Build, Test, or Coverage is project text: it is moved to just after the
end marker and left there. Any other non-empty line that sat inside the
markers and is absent from the upgraded file is appended the same way
(see `preserving N hand-written line(s)…` in the preview). A language
with neither a detected command nor an existing command is omitted, and
the preview lists it under `Gates left unset`.

When no project manifest is present (`package.json`, Makefile, justfile,
`pyproject.toml`, or a workflow file), unmatched gates keep the template
command prefixed with `UNVERIFIED: confirm` rather than being omitted.
A manifest that defines no matching lint/build/test omits those gates
instead of inventing them.

The header is read from either `> **Languages**: python` or
`> **Languages:** python`, and the same two forms of `Type`.

Section I is `evals/fixture/` plus `docs/evals/SCORE.md`. Claude Code and
Codex are `not run`. The Cursor column records one run. A missing eval is
not a pass. That one run does not show the generated files changing the
result.

Do not run this generator against the golden-agents checkout in order to
refresh this repo's own `AGENTS.md`. That file is the operator manual. It has
framework markers and no `> **Languages**:` line. Forcing `--language=shell`
replaces the manual's real shell gates with `UNVERIFIED` template commands.

## 7. Mirrors, Copilot, context-management, and review cost

Redirect mirrors (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`)
are short `@AGENTS.md` imports. `COPILOT.md`, `CODEX.md`, and `AGENT.md` are
retired: a generated stub is removed; a hand-written copy is left alone.
GitHub Copilot's kept path is `.github/copilot-instructions.md`, not
`COPILOT.md`.

`context-management` is not a progressive trigger. Token and session
guidance lives in modules when selected; do not expect a "conversation
exceeds 50 exchanges" line inside the framework block.

Expect a large framework diff. Review cost is in the project text after the
end marker and in any `preserving N hand-written line(s)…` preview lines,
not in every regenerated framework paragraph. Confirm those before merge.

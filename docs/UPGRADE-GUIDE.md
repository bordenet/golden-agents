# Upgrade guide

Audience: an AI agent working in a consumer repo that was generated by
golden-agents 1.4.x before this fix stack. Example consumer:
https://github.com/bordenet/superpowers-plus/

This guide matches the generator on `main` after items 1-21 and design v2
sections A-H. Section I is the eval fixture. Claude Code and Codex have no
score. The Cursor column has one run, and the two columns of that run match.
The commit `26d0b82` does not have the safe-write, backup, or stamp
behavior described here.

Do not assume templates or the script live at `$HOME/.golden-agents`. Run
`generate-agents.sh` from the golden-agents checkout that contains these
fixes. Pass the consumer repo with `--path`.

Do not edit `generate-agents.ps1`. It only runs the shell script.

## 1. Detect the generator version

Read `AGENTS.md`. If that name is absent and `Agents.md` is a different file,
read `Agents.md` too.

1. If a line matches
   `<!-- golden-agents:stamp version=VERSION updated=YYYY-MM-DD -->`,
   the generator version is `VERSION`.
2. Otherwise, if the header contains `> **Generated by**:` with `v1.4.` and
   the file contains both `<!-- GOLDEN:framework:start -->` and
   `<!-- GOLDEN:framework:end -->`, treat it as 1.4.x from before the stamp.
   Upgrade keeps that header until the framework block bytes change, and it
   does not insert a stamp into a file that does not already have one.
3. If there is no stamp and no framework marker pair, stop. Ask a human.
   Do not write.

## 2. Back up every guidance file before any write

Copy each file that exists. Use a timestamp the shell can format without
GNU `date -d`:

```bash
ts=$(date +%Y%m%d-%H%M%S)
bak() {
    src=$1
    dest="${src}.${ts}.bak"
    n=1
    while [ -e "$dest" ]; do
        dest="${src}.${ts}.bak-${n}"
        n=$((n + 1))
    done
    cp "$src" "$dest"
    echo "$dest"
}
```

Back up, when present:

- `AGENTS.md`
- `Agents.md` only when it is a different file from `AGENTS.md`
  (`[ ! AGENTS.md -ef Agents.md ]`)
- `CLAUDE.md`
- `GEMINI.md`
- `CODEX.md`
- `AGENT.md`
- `COPILOT.md`
- `.github/copilot-instructions.md`
- `.ai-guidance/invariants.md`

Do not add `*.bak` to `.gitignore`.

`--upgrade --apply` also writes `AGENTS.md.backup`. That copy is in addition
to the timestamped `.bak`, not a substitute. `--adopt` and `--migrate` write
their own timestamped `.bak` files and, for adopt, `AGENTS.md.original`.

## 3. Upgrade without losing project text

Preview first. The preview must not change the file.

```bash
/path/to/golden-agents/generate-agents.sh --upgrade --path=/path/to/consumer
```

Read the diff before applying.

- Text after `<!-- GOLDEN:framework:end -->` must be unchanged, unless this
  run passes `--superpowers`. Then the only allowed addition is the
  superpowers block immediately after that marker. A bootstrap the project
  already had below the marker must still be there, once.
- If a command the project actually runs becomes `UNVERIFIED: confirm`, stop.
  Do not apply. A matching tail does not make that replacement safe. Show
  the diff to a human.
- A `<!-- golden-agents:modules ... -->` comment next to the stamp, or
  immediately before the framework start when the file has no stamp, is
  expected. Do not delete it.

Then apply:

```bash
/path/to/golden-agents/generate-agents.sh --upgrade --apply --path=/path/to/consumer
```

Rules:

- A plain run (no `--upgrade`, `--adopt`, or `--migrate`) that finds a
  non-generated redirect or any existing `AGENTS.md` must exit 1 and write
  nothing. Do not delete those files to make a plain run succeed.
- Use `--upgrade` only when both framework markers are present.
- Use `--migrate` or `--adopt` only when the script tells you to, and only
  after the backups in section 2.
- Do not overwrite an existing `.ai-guidance/invariants.md`. The script keeps
  it. If the file is absent, the script creates it from the template.

## 4. Verify with runnable checks

In the consumer repo, after `--upgrade --apply`:

```bash
# Both markers still exist.
grep -n 'GOLDEN:framework:start' AGENTS.md
grep -n 'GOLDEN:framework:end' AGENTS.md

# Project text after the end marker.
awk 'f { print } index($0, "<!-- GOLDEN:framework:end -->") { f = 1 }' AGENTS.md > /tmp/after-project.txt
awk 'f { print } index($0, "<!-- GOLDEN:framework:end -->") { f = 1 }' AGENTS.md.*.bak > /tmp/before-project.txt
```

If this run passed `--superpowers` and the only new tail text is that block
immediately after the end marker, delete that added block from
`/tmp/after-project.txt`. Then run:

```bash
cmp /tmp/before-project.txt /tmp/after-project.txt
```

`cmp` must exit 0. If it does not, restore `AGENTS.md` from the `.bak` and
stop. Do not leave the applied file in place. Any other tail difference is
a failed upgrade.

In the golden-agents checkout:

```bash
shellcheck generate-agents.sh
bats test/safe-write.bats test/data-loss.bats test/upgrade.bats test/stamp.bats
```

## 5. Recover a redirect that was replaced by a stub

Look for a modification that turned real content into a short generated file:

```bash
git log --oneline --diff-filter=M -- CLAUDE.md GEMINI.md CODEX.md .github/copilot-instructions.md AGENTS.md
```

Show the earlier blob. Do not restore it yourself.

```bash
git show COMMIT:CLAUDE.md
```

If that blob is real project text and the worktree file is a stub, print both
and stop. A human decides whether to put the old content back.

## 6. What the upgrade already does

Sections A-H of `docs/DESIGN-v2.md` are in this generator. `--upgrade --apply`
writes the redirect imports, the module copies, the scoped rules, the
`<!-- golden-agents:modules ... -->` comment, the current template wording,
the token estimate on stdout, the human-merge self-manage block, and the
detected quality gates. Do not copy those in by hand.

Pass `--superpowers` only when the consumer asked for that block. It is
written after `<!-- GOLDEN:framework:end -->`. Without the flag, upgrade
removes the block from the framework region and does not put it back.

Gate detection matches only the exact names `lint`, `test`, `build`, and
`coverage`. A step named `Run BATS tests` or `Run ShellCheck` does not match.
On a new file, an unmatched gate keeps the template command and is prefixed
with `UNVERIFIED: confirm`. On upgrade, a command already in the quality-gate
block is kept when it is that language's template command, or when it matches
no selected language's template. A language with neither a detected command
nor an existing command is omitted, and the preview lists it under
`Gates left unset`.

Section I is `evals/fixture/` plus `docs/evals/SCORE.md`. Claude Code and
Codex are `not run`. The Cursor column records one run. A missing eval is
not a pass. That one run does not show the generated files changing the
result.

Do not run this generator against the golden-agents checkout in order to
refresh this repo's own `AGENTS.md`. That file is the operator manual. It has
framework markers and no `> **Languages**:` line. Forcing `--language=shell`
replaces the manual's real shell gates with `UNVERIFIED` template commands.
